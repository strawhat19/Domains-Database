# Domain Marketplace

`/market` opens the domain marketplace on web and native. `/auction` opens the Owner-only Auctions Beta preview, available under **Market** in the header. The switcher below each page links between them. `/market?listing=<id>` opens a public listing and returns signed-out buyers to it after signing in or creating a Free account. Older `/auction?listing=<id>` links forward to the Market listing.

**Browse** includes public Afternic Premium discovery through GoDaddy. The server uses `GODADDY_PAT` with the `domains.domain:read` scope and shows domains explicitly identified as Afternic Premium inventory. The default view shows a sample from a fixed keyword search. Submitting a search checks the exact domain or looks up related Premium names. GoDaddy confirms prices and handles checkout. The seller’s Afternic Portfolio API stays scoped to that seller’s account. [GoDaddy Afternic Premium discovery](https://developer.godaddy.com/en/docs/api-users/changelog/domains-afternic-premium)

## Listing workflow

1. Open **Sell** or choose **List For Sale** from a portfolio domain. Market lets you make your profile public and then choose your seller URL in place. An active seller also needs the **Marketplace Listings** feature and the configured role and plan audience. Starter is the initial minimum tier. An active Owner bypasses the paid-tier requirement and still needs a public profile, the saved global setting, and the role audience.
2. Pick a unique `/domainers/<username>` address for your public profile and seller listings. Existing `/profiles/<username>` and `/sellers/<username>` links and past usernames resolve to the current address. Public profiles show the portfolio’s total domain count and names chosen with **Show On Public Profile** in each domain’s editor. Domains published through Market appear under **Published Listings**. The profile name, avatar, description, and visibility come from your account settings. Private profiles show a visibility notice to visitors.
3. Pick a suggestion from your loaded portfolio or enter a domain yourself. Saved estimates help rank suggestions. Save a draft with a USD Buy Now price, offers enabled, or both. Add the supplied TXT record at the DNS provider, then choose **Verify & Publish**. Keep the record in place while accepting checkout. The server verifies it again before creating a payment reservation. The listing can be paused and edited until a buyer reserves it or an offer is accepted. Domains must be registrar-transferable names. The server uses the ICANN section of the Public Suffix List to reject subdomains.
4. In **Messages**, sellers can accept or decline offers and buyers can withdraw them. One accepted offer can hold a listing at a time. Conversations and their read state are participant-private. The associated order opens the same conversation for registrar transfer after payment. [Stripe setup](marketplace-payments.md)
5. Eligible sellers with the configured Afternic portfolio can import or publish through **Afternic**. The Afternic hold prevents an overlapping in-app sale while the provider listing is present or its status is unresolved. [Afternic setup](marketplace-afternic.md)

## Server and Firestore

Markets uses the existing Expo Node server and Firebase Admin configuration. Web uses same-origin requests. Native uses the app's configured HTTPS site URL, so its server must expose the same APIs. Deploy the reviewed Firestore rules and index manifest to the matching Firebase project. Wait until its `marketplaceListings`, `marketplaceThreads`, and `marketplaceOrders` composite indexes are ready. Client builds do not publish database configuration.

The server projects public records and validates Firebase identity, current account state, and listing or participant permissions. Drafts, claims, handles, offers, order records, checkout reservations, and provider settings are server-managed. The Owner's Marketplace Listings settings live in the server-managed `marketplacePolicies` collection, so older clients can keep using the existing global feature document. Firestore client access is limited to bounded realtime queries for a participant's threads and messages. Marketplace lists use 24-record pages. Chat loads 30 conversations and 50 messages per page. Read state is private and monotonic. Seller URL changes keep up to 20 reserved aliases for existing links.

Use the dedicated Stripe sandbox for payment acceptance tests and configured Afternic credentials to verify that provider's portfolio. A sandbox order records test payment while the listing stays on sale. Verify the production rules and indexes, configured Stripe webhook, and actual seller onboarding before enabling live payment acceptance.

Markets checks checkout readiness for the current origin before showing payment actions. While checkout is unavailable, buyers can still see asking prices, send offers where enabled, and message sellers. The checkout request separately verifies the seller's Stripe account.
