# Page Transition Loader And Home Reveal

Use this workflow for “give me page transition loader into home page,” for a loader whose entry or exit snaps, or for a homepage whose pieces appear before their reveal. The loader, destination, and local media loaders should read as one sequence.

## Use The Destination Brand

- Find the actual root shell, route loading boundary, theme source, and existing logo variants. Use the current approved mark, destination fonts and palette, and contrast tokens. Preserve logo geometry, spacing and proportions. Pick a backdrop, divider, or panel motion that fits the app. A textured split panel and glowing center seam are optional treatments for a theme that suits them. For an existing loader, preserve its approved composition when adding motion.
- Pick a stable, opaque base surface for the first paint. Set aside room for the mark, status, and progress from the start. Use a local asset or a theme-color fallback for a slow image. Preload a critical decorative texture when appropriate and fade it after decoding. Avoid a large media or font dependency on the first frame.
- Keep the loader in a shared route shell where practical. Use the framework’s existing route and readiness lifecycle. On native, bridge the platform’s launch screen into the branded view, preserve the safe area, and use supported animation and accessibility APIs.

## Stage The Entrance, Progress, And Exit

1. **Enter once.** On hard refresh, prerender a solid covering surface and start the decorative entrance when the client is ready to animate it. Match the prerender and client states so hydration cannot replay an entrance or show the destination between frames. Give the static cover a finite escape if scripts or hydration fail. Reveal an already usable page or a readable fallback with a way to retry. Keep route access and actual readiness governed by the app. On an in-app transition, bring the cover in before the destination is exposed. Fade or draw in the logo, labels, frame, and surface layers on coordinated tracks. If the design has a seam, fade in the dark join before the highlight grows. Keep an opaque backing under any initial seam gap.
2. **Show honest progress.** For measurable work, show smooth progress driven by real readiness. If a designed count or sweep is requested, show it at zero when the entrance becomes readable, ease it toward completion, and give the completed display a short beat before exit. When both are shown, keep the real readiness as a smaller, distinct secondary meter with the accessible progress semantics. Advance real readiness only for tracked milestones such as route data, destination shell, or theme restoration. Use an indeterminate status when there is no reliable measurement. Hold the visual completion until the usable view or its real fallback can be shown. Bound optional waits and show an accurate fallback status if startup is slow or fails.
3. **Retain the exit.** Keep the cover mounted as its labels, mark, and panels leave. Let the main exit animation finish before removing it. Listen to the intended animation or transition on its owning element and use a bounded timeout fallback for missing events. Child animation events must not release the cover early. Cancel pending frames, timers, and listeners when a navigation supersedes the current transition or the shell unmounts. Preserve focus, scrolling, history, and link behavior.
4. **Hand off once.** Prepare the first-screen reveal styles while the cover still hides them, then release from the actual exit lifecycle rather than from unrelated mount times. No destination element should appear at full strength, hide, and then animate. Keep the layout stable and let each visible part have one entrance owner. Tune timings against the destination. A short entrance around 180–360 ms, an exit around 360–600 ms, and a content handoff around 400–700 ms can be practical starting points rather than required durations.

## Cover The Whole First Screen

- Audit the first visible viewport at several sizes. Include the logo and nav, utility strip or marquee, header and top-bar rules, hero heading and supporting copy, primary action and search, feature art and its decorative frame or ring, shadows, captions, counters, control clusters, rating or stat rules, separators, first visible category or result strip, and card shells. Check both the loaded and placeholder states. Decorative edges often appear static even when everything inside animates.
- Keep groups visually coherent. Let a card and its contained controls reveal as one, or give independent siblings distinct motion. Avoid applying an entrance to both a parent and an animated child. Preserve the settled spacing, button geometry, focus rings, sticky layout, and active hover or scroll motion. Animate border paint or a reserved divider layer so the layout does not shift.
- Reveal a marquee through its viewport or another independent layer. The entrance must leave the repeating track’s transforms, loop seam, and edge fade intact. Opening unrelated controls or restoring focus must not restart or pause it. When clipping paired actions, an opposing direction on the second action and a short stagger can distinguish them if that suits the design.
- If prominent media has an existing branded or distorted crest loader, give the loader itself a short visible entrance. Prewarm critical media under the cover when doing so does not threaten the first reveal. Hold the local loader briefly only if needed to read the entrance, then fade it directly to ready media or a stable fallback. Keep decorative reveals separate from the media’s own track. Defer heavy below-fold initialization until it approaches the viewport, and reserve the media dimensions.
- Let below-fold panels and cards reveal once when they enter view. Register content that mounts late; use one owner per semantic group. Keep live announcements, error states, and focusable controls usable while their visual layers change. Promote waiting interactions to the visible state immediately on focus, and prevent stale reveal states after cancellation. Reduced motion should keep the useful loading state and destination visible while skipping the decorative timing, motion, and forced dwell. If animation APIs are missing, show the UI in its settled state.
- Drive the homepage handoff from the same route state as the overlay. Arm eligible elements before the doors expose them, release above-fold elements together, then use viewport entry for the rest. Explicitly opt plain navigation links into the same clip used by buttons. Keep the marquee and fixed or sticky surfaces outside the general content observer, and animate their intended visual layers independently. Validate any optional delay before passing it to the animation API since a boolean data attribute may arrive as the string `true`. Use the default stagger for missing or nonnumeric delays.

## Coordinate The State Boundaries

| Phase | What owns the visible result |
| --- | --- |
| Initial cover | The route shell paints an opaque base. Hold the decoration in its starting pose until hydration, and reserve the destination layout. |
| Enter and wait | The loader owns the screen. Track shell and theme readiness separately from optional decoded textures or media. A late texture fades over the base when available. |
| Exit | The overlay stays mounted. Drive panel movement, logo fade, and any seam or boundary from the exit phase. Associate completion and fallbacks with the current navigation so a stale event cannot release a newer transition. |
| Destination reveal | The handoff releases the prepared header, hero, and visible sections once. Scroll targets retain their own first intersection, and persistent chrome or ambient loops keep their own state. |
| Media handoff | The feature preview uses its own loading and ready states. A stable surface and reserved space cover slow or unavailable media, so text, controls, and layout can finish their entrances independently. |

Treat the overlay’s removal as the end of its visual lifecycle. Release the content when the exit reaches the point where those layers should become visible. Keep the overlay nonblocking once the destination is interactive, and handle focus on a waiting control by revealing that control immediately. Use elapsed time for animated counters and clear stale callbacks when the route changes.

For a quick media load, start a short decorative dwell when the local loader actually becomes visible. A completed warmup may coexist with an active visual loader. Keep the visual dwell out of status announcements and skip it for reduced motion. If loading is still real, keep the loader active until media or fallback is ready without replaying its entrance. Pause glitch, scan, or other ambient loops while the loader is covered, inactive, or offscreen. Crossfade once into the settled preview. Keep masks or transforms for an orbit, interactive preview, or running marquee on separate layers so one entrance cannot reset another effect.

## Review The Handoff

- Review source and, when runtime validation is authorized, capture a hard refresh from before exit through the first settled frame. Compare the last covered frame, first revealed frame, and intermediate frames. Inspect the route handoff too when the same loader owns it. Compare only the renders actually exercised.
- Include desktop and mobile, available theme modes, repeat or interrupted routes, reduced motion, a focus shortcut, and slow assets or data where relevant. Check that the title and live labels stay readable, decorative layers do not jump ahead, exits never hang, late-ready media crossfades once, control geometry stays steady, and early work does not stall the visual sequence. Check the browser console, especially for invalid animation timing from optional DOM attributes. Separate source review from browser or device evidence.

| Symptom | Check first |
| --- | --- |
| An element flashes, hides, then reveals | Compare the initial server markup, hydrated waiting state, first uncovered frame, and release. Check for late theme or asset swaps, and multiple reveal owners on the same element or its ancestors. |
| A border, count, link, or loader appears fully formed | Inspect its own paint layer or target selector. Include pseudo-elements, plain links, badge overflow, and content near the fold. Keep status announcements intact when animating visual counts. |
| The exit snaps or stalls | Verify the event target and animation name, route identity, and timeout relative to the complete exit including CSS delays. Check the no-motion path and that optional media cannot hold the shell. |
| The screen pauses and then jumps ahead | Look for long work immediately after dismissal. Compare frames with media initialization and defer work for viewers or sections outside the viewport. |
| A local console still shows a timing error | Confirm the exact origin and the served bundle contain the fix. Reproduce with a clean console and hard refresh before treating a retained entry or older client bundle as a new failure. |
