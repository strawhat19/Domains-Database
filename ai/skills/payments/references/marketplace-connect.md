# Multi-Seller Marketplace Payments (Stripe Connect)

Read this only when a requested marketplace lets other users sell to buyers and receive payouts. A single-merchant store keeps one merchant account ([shop system](../../shop/references/system.md)). Subscription billing keeps its own separate Stripe configuration and keys ([Stripe billing](stripe-billing.md)).

1. Sellers onboard through Stripe-hosted onboarding into a connected account (Accounts v2 recipient configuration with the Express Dashboard). The server creates Account Links and Express login links; the client only opens them.
2. When delivery happens after payment (domain transfers, services, anything not instant), use separate charges and transfers (charge on the platform via Checkout with a transfer_group, then call transfers.create to the connected account only after delivery is confirmed, buyer confirms, or a dispute/timeout window passes), or delayed/manual payouts on the connected account. Destination charges are acceptable only when delivery is immediate and verifiable. The server, not the client, decides the price: a fixed listing price or an accepted offer it reads from its own records. The platform fee is an application fee computed server-side in integer cents; document that it is gross commission and that Stripe processing/Connect fees come out of the platform's share.
3. Re-verify listing eligibility (ownership proof, seller state, payout capability) on the server immediately before creating a checkout reservation. Hold a server-only checkout lock so one listing or accepted offer cannot be sold twice.
4. Confirm payment only from a signed webhook plus Stripe API readback (checkout.session.completed, async_payment_succeeded/failed, expired, charge.updated). A success return URL leaves the order pending. Record payment idempotently.
5. Track seller funds separately from payment: record whether the transfer to the connected account succeeded, and flag the order for review when Stripe skips the transfer because the seller lost the capability. Refunds, disputes, reversals and skipped transfers are platform responsibilities. A refund path must exist for orders whose delivery never completes, and funds must not be released to the seller before delivery is confirmed.
6. Keep connected account IDs, session IDs, orders, locks and seller payment records in server-only collections; public listings get an explicit projection. Use a dedicated marketplace secret key with only the Connect/Checkout/read scopes it needs.
7. The client validates every provider URL it opens: HTTPS, no port or credentials, host allowlisted to checkout.stripe.com or connect.stripe.com. Bind requests to the current Firebase identity and reject the response if the account changed mid-request; use a timeout and typed error codes.
8. Sandbox orders record test payment without changing live listing state; only confirmed live payment marks a listing sold. Report Connect activation, webhook delivery and settlement as separate evidence levels per [Payments](../SKILL.md#completion-evidence).
