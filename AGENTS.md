# AI Instructions

This file is Rakib's (strawhat19) shared development pack. The canonical copy is the private repository https://github.com/strawhat19/AI. Detailed skills, references, scripts, and [maintenance](ai/maintenance.md) live in [ai/](ai/README.md). To build a new app in the style of an existing one, read [TEMPLATES.md](https://github.com/strawhat19/AI/blob/main/TEMPLATES.md) at this repository's root, then read that app's live GitHub repository.

Apply these preferences across projects and workspaces, within the requested task's scope. Other projects keep a short root `AGENTS.md` that tells agents to follow this pack and then lists only project-specific overrides: name, domain, colors, and unique features.

Ask Rakib in chat and wait for an explicit yes before changing any repository other than https://github.com/strawhat19/AI. This repository is the allowed place to update the shared pack. Do not delete `ai/` from another project until Rakib explicitly says yes for that project.

1. Make practical, minimal code changes and preserve existing uncommitted work. Do not verify, test, build, or run UI checks unless I ask. Feature-branch commits, review, and merging to main follow [Git Workflow](ai/skills/git-workflow/SKILL.md). If an app is actively running, batch edits into a final save when practical, or safely stop and restart it to reduce save churn. During source reviews, look for compiler, type, lint, and editor issues where practical; use red for errors and yellow for warnings when supported.

2. Prefer Christmas-tree ordering for imports, props, object fields, arrays, and grouped declarations: shortest lines first, then longer lines. Keep imports at the top and preserve readable execution order and framework conventions. Prefer readable names and arrow functions where they fit; add comments only for non-obvious behavior.

3. Prefer SCSS over CSS where supported. In hand-written SCSS and CSS, break each rule into multiple lines with one declaration per line and exactly one blank line between adjacent blocks. Use the platform's supported style objects for native views. Follow the [stylesheet formatting guidance](ai/skills/structure/structure.md#stylesheet-formatting).

4. Give actual rendered app-owned web elements unique descriptive IDs and stable semantic classes shared by the same purpose, including repeated siblings. Repeated IDs need component-instance, record and element-role scope; preserve existing classes, anchors and behavior IDs. React keys, generated style hashes and data attributes do not replace actual classes. Give repeated rendered collections a named logical parent, reusing valid list/table/scroll/group containers and preserving layout, drag/drop and virtualization. Native uses nativeID and supported platform metadata rather than CSS classes. Follow [Element Identifiers And Collection Parents](ai/skills/structure/references/element-identifiers.md) for framework adapters, stable instance IDs and safe grouping.

5. Prefer icons with text for buttons and clickable items, or an icon alone with an accessible label. For Profile and Admin actions, prefer shared square icon-only buttons with descriptive accessible labels, web tooltips, clear pending/disabled states and larger touch targets; keep navigation, field and choice labels readable. Keep navigation icons consistent. For table statuses, use the shared users-table pattern with actionsCell, rowStatus, statusDotWrap, statusDot, and statusText classes and green, gray, or red state colors.

6. Prefer smooth transitions and respect reduced-motion settings when available. Aim for Awwwards-level pages with clean space around the logo, deliberate typography, and subtle motion inspired by Daniel Snows. Keep motion quiet. Logo concepts and mockups still follow the design skill in rule 18. For “give me page transition loader into home page,” use [Page Transition Loader and Homepage Reveal](ai/skills/scroll-reveals/references/page-transition-loader.md) and [Scroll Reveals](ai/skills/scroll-reveals/SKILL.md). Use the destination's own logo, palette, and layout, and coordinate first paint, loader exit, and one visible content reveal per element.

7. Break JSX props and children onto separate lines when it improves readability. Keep simple code compact, for example:

```tsx
<Text
  {...elementProps(`action-label`, item.id)}
  style={[styles.label, { color: active ? palette.blue : palette.muted }]}
>
  {label}
</Text>
```

8. In JavaScript, TypeScript, JSX, and TSX, prefer backticks, then single quotes, with double quotes as a last resort. Use single quotes for import paths and optional chaining around nullable values, arrays, API responses, and nested model fields when practical. Use concise Title Case console labels, logs, and toasts, with (s) where useful and no trailing period unless needed.

9. For new apps, use Expo, React Native, TypeScript, SCSS, and GSAP for web and mobile unless Rakib chooses another framework. Use Expo web for sites. Do not start a new site on Vite. Follow the existing framework when editing an app. Preserve the model and speed selected in the Codex UI; do not override them from global config. If none is explicitly selected, prefer gpt-5.4-mini with medium reasoning. Before complex architecture, broad refactors, tricky debugging, risky migrations, security-sensitive code, or long multi-file work, recommend gpt-5.5 fast when its capability is worth the cost.

10. Each app should support web on a custom domain and either a PWA or a mobile app deployable to an app store.

11. Keep shared state under shared/: React Context for React apps, or services for Angular. Separate concerns such as the current user, users, theme, and application data. Keep public app browsing available unless I request a private app; prompt for sign-in or sign-up when an action requires identity. Account connection credentials belong to private account-scoped storage, separate from public User records. For Firestore documents, use app-owned IDs shaped Type_Number_Name_Date_UUID, with an auto-incrementing integer number matching the ID. Store external service IDs in named fields such as stripe_order_id instead of primary IDs.

12. Give each component its own folder, separating logic, rendering, and styles. Share behavior across web and native views where practical.

13. Headers have a component variable named sticky, defaulting to true. Keep the header and attached top bars sticky together. On scroll, smoothly apply a semi-transparent surface and blur; place backdrop-filter after -webkit-backdrop-filter. Measure the shared header/safe-area height for attached account layouts. Header utility focus, popup opening and focus restoration must not pause an unrelated marquee; preserve reduced-motion preferences. Follow [Navigation Icons and Badges](ai/skills/structure/references/navigation-icons-and-badges.md) for compact link spacing, optically balanced glyphs, fixed button dimensions, and themed Beta badges.
