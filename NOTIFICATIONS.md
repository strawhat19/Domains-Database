# Notifications

The Admin Notifications section saves global announcements in Firestore `notifications`. Active notices appear in the public bell and notification pages; Draft appears as Inactive in the editor, and Archived remains a valid persisted status for older records. Owner, Admin, and the legacy Administrator role can create, edit, change status, and delete announcements. Developer accounts cannot read inactive notices or manage announcements. Every mutation checks the authenticated account and its current active role; Firestore rules enforce the same access.

Deploy this repository’s `firestore.rules` and `firestore.indexes.json` to the app’s Firebase project before using notification management. The active feed needs the `active` and descending `number` composite index. Admin paging and legacy slug collision checks use the configured `number`, `slug`, and `providerId` indexes. This source update does not deploy rules, indexes, or documents.

New records have app-owned `Notification_Number_Name_Date_UUID` IDs with matching integer numbers. A transaction advances `counters/notifications` and reserves a unique slug in `notificationSlugs`. Editing preserves identity and creation time; deleting retains the counter so a number cannot be reused. Legacy records keep their IDs and `providerId` aliases, including the original development and support links. Saved timestamps are normalized into ISO strings for app consumers.

The public subscription returns the latest 100 active notices. Admin subscriptions return pages of 50 with a numbered cursor and a server-confirmed snapshot. Dashboard counts describe the loaded page. Empty collections remain empty; inactive or deleted notices have no sample fallback. `populateInitialAnnouncements()` is an explicit legacy import operation, not a sign-in or page-load effect, and cannot repeat after its persisted import marker has been set.

Personal notifications continue using private account storage through the existing notification facade. Individual and Mark All Read actions store a separate versioned read-ID list in each account’s private storage, and synchronize through the existing Firestore storage adapter. Read actions wait for that saved state to load, and Reload remains available after a read-preference failure. Profile account-data reset clears the read preferences. Guests keep read preferences only for the current session. Global announcement status is unaffected by read actions. Existing private connection credentials are not exposed to administrators.

The explicit local demo mode uses the existing local announcement snapshot, retains monotonically increasing numbers, and labels account read preferences as device-local. Production Firestore connection, permissions, index, and malformed-record failures are surfaced instead of showing sample records or silently resetting persisted data.
